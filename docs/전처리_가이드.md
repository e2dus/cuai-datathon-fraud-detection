# 전처리 가이드

> 파랑 = 정상 / 빨강 = 사기  
> 시각화를 보고 작성한 전처리 방향 메모 (시각화가 추가될수록 업데이트)

---

## 1. 변수 유형 분류

### 이진형 (0 / 1 두 개의 스파이크만 존재)


| 변수                      | 관찰                                         | 전처리 방향                     |
| ----------------------- | ------------------------------------------ | -------------------------- |
| `is_free_email`         | 사기 쪽에서 1(무료 이메일) 비율이 눈에 띄게 높음 → **분리력 있음** | 그대로 사용. Target Encoding 고려 |
| `is_home_phone_valid`   | 사기 쪽에서 0(유효하지 않음) 비율이 더 높음                 | 그대로 사용                     |
| `is_mobile_valid`       | 두 클래스 간 차이가 소폭 존재                          | 그대로 사용                     |
| `is_session_persistent` | 두 클래스 분포 유사                                | 그대로 사용, 영향 미미할 수 있음        |
| `is_foreign_req`        | 두 클래스 분포 유사                                | 그대로 사용                     |
| `has_other_cards`       | 두 클래스 분포 유사                                | 그대로 사용                     |


---

### 강하게 오른쪽으로 치우침 (Heavy Right-Skew)

> 공통 처리: `log1p` 변환 또는 `clip` 후 `log1p`


| 변수                    | 관찰                           | 전처리 방향                                  |
| --------------------- | ---------------------------- | --------------------------------------- |
| `session_length_min`  | 0~10분에 극단적으로 몰림, 긴 꼬리        | `log1p` 변환                              |
| `req_rate_8h`         | 0 근처에 몰림, 긴 꼬리               | `log1p` 변환                              |
| `req_rate_24h`        | 4000~5000 부근 두 봉우리 (이봉 분포)   | `log1p` 또는 구간 피처 (높은 구간 = 플래그)          |
| `req_rate_4w`         | **세 개의 뚜렷한 봉우리** — 매우 독특한 분포 | 구간(bin) 피처 생성 권장. 각 봉우리가 다른 행동 패턴일 수 있음 |
| `branch_req_count_8w` | 0에 몰림, 긴 꼬리                  | `log1p` 변환 또는 `>0` 이진 플래그 추가            |
| `dob_email_count_4w`  | 0~5 구간에 몰림                   | `log1p` 변환                              |
| `zip_req_count_4w`    | 0 근처에 극단적으로 몰림               | `log1p` 변환, `>0` 이진 플래그 추가              |
| `req_credit_limit`    | 0~500에 몰림, 긴 꼬리              | `log1p` 변환                              |
| `device_email_cnt_8w` | 1에서 스파이크, 이후 감소              | `log1p` 또는 그대로 사용                       |


---

### 분리력이 특히 강한 변수


| 변수                  | 관찰                                                                                | 전처리 방향                            |
| ------------------- | --------------------------------------------------------------------------------- | --------------------------------- |
| `name_email_sim`    | **이봉 분포**: 사기(빨강)는 낮은 값(이름-이메일 유사도 낮음)에 크게 몰림. 정상(파랑)은 높은 값에 더 몰림 → **가장 강한 분리력** | 그대로 사용 + `< 0.3` 이진 플래그 추가 강력 권장  |
| `credit_risk_score` | 사기는 낮은 점수 구간에 봉우리가 더 높음. 범위가 -200~400으로 넓음                                        | 그대로 사용. 음수 구간(`< 0`) 이진 플래그 추가 고려 |
| `days_since_req`    | 사기는 낮은 값(최근 신청)에 더 몰리는 경향                                                         | 그대로 사용 + 낮은 구간 플래그 (예: `< 7일`)    |


---

### 이산형 정수 (정수 값에서만 스파이크)


| 변수                  | 관찰                                      | 전처리 방향                            |
| ------------------- | --------------------------------------- | --------------------------------- |
| `age_bucket`        | 10~90 사이 정수 단위 스파이크 (10대 단위 연령 버킷으로 보임) | 그대로 사용 또는 카테고리로 처리                |
| `bank_months_count` | 0~30 사이 정수 스파이크, 오른쪽 꼬리                 | 그대로 사용. 0인 경우(은행 거래 없음) 이진 플래그 추가 |
| `month_idx`         | 0~8 사이 균등한 정수 스파이크 (월 인덱스)              | 범주형으로 처리하거나 sin/cos 순환 인코딩 고려     |


---

### 특이 사항 — 음수 or 이상 범위 값


| 변수                     | 관찰                                                      | 전처리 방향                                  |
| ---------------------- | ------------------------------------------------------- | --------------------------------------- |
| `init_transfer_amt`    | -25 ~ 100 범위, 0 근처에 스파이크. **음수값 존재** → 센티넬(-1)이거나 실제 음수 | 음수값을 NaN 또는 별도 플래그로 처리 후 확인 필요          |
| `device_fraud_history` | -0.4 ~ 0.4 사이 이봉 분포. 음수값 존재 → 정규화된 값이거나 센티넬             | 분포 범위가 좁아 이미 스케일링된 것으로 추정. 음수 구간 플래그 추가 |


---

### 분포 차이 미미 (우선순위 낮음)


| 변수                 | 관찰                     |
| ------------------ | ---------------------- |
| `yearly_income`    | 다봉 분포, 두 클래스 분포 거의 동일  |
| `prev_addr_months` | 오른쪽 치우침, 두 클래스 분포 유사   |
| `curr_addr_months` | `prev_addr_months`와 유사 |


> 위 변수들은 단독으로는 분리력이 낮을 수 있으나, **다른 변수와의 교차항**으로는 유효할 수 있음.

## 2. 우선순위 액션 리스트

### 즉시 적용

1. `name_email_sim < 0.3` 이진 플래그 생성 (가장 강한 사기 신호)
2. `is_free_email` 그대로 유지
3. `credit_risk_score < 0` 이진 플래그 생성

### log1p 변환 대상

`session_length_min`, `req_rate_8h`, `branch_req_count_8w`, `dob_email_count_4w`, `zip_req_count_4w`, `req_credit_limit`

### 구간(bin) 피처 생성 권장

- `req_rate_4w` — 세 봉우리가 서로 다른 행동 패턴을 의미할 가능성 높음
- `req_rate_24h` — 이봉 분포의 경계값 파악 후 이진 구분
- `days_since_req` — 7일 이내 / 이외 구분

### 추가 확인 필요

- `init_transfer_amt` 음수값 의미 확인 (센티넬인지 실제 음수인지)
- `device_fraud_history` 스케일 확인

### 중앙값 차이로 본 분리력 재확인 (★ 많을수록 강함)


| 변수                      | 방향                         | 분리력 | 비고                                         |
| ----------------------- | -------------------------- | --- | ------------------------------------------ |
| `name_email_sim`        | 사기 박스가 훨씬 왼쪽(낮음)           | ★★★ | Histogram 분석 강력 재확인                        |
| `credit_risk_score`     | 사기 박스가 왼쪽(-2.5~0), 정상은 오른쪽 | ★★★ | 낮은 신용점수 = 사기                               |
| `is_free_email`         | 사기 박스가 오른쪽(1에 가까움), 정상은 왼쪽 | ★★  | Histogram 분석 재확인                           |
| `is_home_phone_valid`   | 정상 박스가 오른쪽(유효), 사기는 왼쪽     | ★★  | Histogram에서는 미미했으나 박스에서 차이 확인              |
| `is_session_persistent` | 정상 박스가 오른쪽, 사기는 왼쪽         | ★★  | Histogram에서 미미해 보였으나 실제 차이 있음 → **재평가 필요** |
| `prev_addr_months`      | 사기 박스가 훨씬 왼쪽(0에 가까움)       | ★★  | Histogram에서 유사해 보였으나 실제 차이 있음 → **재평가 필요** |

> ⚠️ `is_session_persistent`, `prev_addr_months`, `curr_addr_months`는 히스토그램에서 차이가 작아 보였으나 박스플롯에서 중앙값 차이가 확인됨. **분리력 있는 변수로 재분류.**

## [시각화 3] Violin plot — 전체 피처 (정상 vs 사기)

> 바이올린 너비 = 해당 값에 데이터가 얼마나 몰리는지.  
> 박스플롯보다 분포 형태(어디가 두꺼운지)가 명확하게 보임.

---

### ★ 새로 발견: `init_transfer_amt` — 이전보다 분리력 훨씬 강함

히스토그램·박스플롯에서는 이상치 정도로만 보였는데, 바이올린에서 명확히 드러남.

- 정상(파랑): 거의 모든 값이 0에 몰린 매우 좁은 바이올린
- 사기(빨강): 높은 값(100 이상)에서 **넓은 풍선 모양** → 높은 초기 이체금액이 사기 신호

**→ `init_transfer_amt > 임계값` 이진 플래그 강력 추천. 우선순위 상향.**

---

### 바이올린으로 분리력 재확인 및 업데이트


| 변수                      | 바이올린 형태                                  | 분리력 | 판단                       |
| ----------------------- | ---------------------------------------- | --- | ------------------------ |
| `name_email_sim`        | 정상은 위(높은 유사도)가 넓음, 사기는 아래(낮은 유사도)가 넓음    | ★★★ | 기존 분석 재확인                |
| `credit_risk_score`     | 정상은 높은 점수(200~400) 구간이 넓음, 사기는 낮은 구간에 몰림 | ★★★ | 기존 분석 재확인                |
| `init_transfer_amt`     | 정상은 0 근처 가늘게 집중, 사기는 높은 값에서 넓음           | ★★★ | **신규 발견 — 우선순위 대폭 상향**   |
| `days_since_req`        | 정상은 위(긴 대기)가 크게 넓음, 사기는 아래(최근 신청)에 집중    | ★★★ | 기존 분석 재확인 — 바이올린에서 더욱 뚜렷 |
| `prev_addr_months`      | 정상은 위(긴 거주)까지 넓음, 사기는 아래(단기 거주)에 집중      | ★★  | 기존 분석 재확인                |
| `curr_addr_months`      | `prev_addr_months`와 동일 패턴                | ★★  | 기존 분석 재확인                |
| `is_free_email`         | 정상은 0 근처가 넓음, 사기는 1 근처가 넓음               | ★★  | 기존 분석 재확인                |
| `is_home_phone_valid`   | 정상은 1(유효)이 넓음, 사기는 0(무효)이 넓음             | ★★  | 기존 분석 재확인                |
| `is_session_persistent` | 정상은 1(지속 세션)이 넓음, 사기는 0이 넓음              | ★★  | 기존 분석 재확인                |


---

### 분포 형태로 새로 파악한 것


| 변수                  | 바이올린 형태                                                  | 시사점                                 |
| ------------------- | -------------------------------------------------------- | ----------------------------------- |
| `age_bucket`        | 두 클래스 모두 여러 층(discrete 버킷)의 울퉁불퉁한 바이올린. 사기는 특정 연령대에 더 집중 | 연령 버킷 자체를 범주형으로 처리하거나 특정 연령대 플래그 고려 |
| `req_rate_4w`       | 두 클래스 모두 3개의 뚜렷한 배(봉우리) 형태 — 분포 형태는 동일하나 크기 비율 다름        | 세 구간 bin 피처 생성 유효. 구간 경계 탐색 권장      |
| `req_credit_limit`  | 정상은 두 개의 봉우리(300, 1000), 사기는 낮은 값(0~300)에 집중             | 300 이하 플래그 또는 두 봉우리 구간 bin 생성 고려    |
| `bank_months_count` | 두 클래스 모두 동일한 울퉁불퉁 패턴(정수형). 분포 거의 동일                      | 분리력 낮음 재확인                          |
| `has_other_cards`   | 사기는 1(다른 카드 있음)에서 뾰족한 스파이크                               | 해석 주의 — 다른 카드 있는 사기가 더 많은 편         |


---

### 분리력 없음 재확인 (제거 또는 낮은 우선순위)


| 변수                     | 이유                                                              |
| ---------------------- | --------------------------------------------------------------- |
| `device_fraud_history` | 두 클래스 모두 거의 선(≈0). 바이올린이 아닌 막대. 정보 없음                           |
| `is_mobile_valid`      | 두 클래스 모두 1에 몰린 동일한 형태                                           |
| `is_foreign_req`       | 두 클래스 모두 0에 집중. 극단값 외에 분리력 없음                                   |
| `zip_req_count_4w`     | 두 클래스 형태 거의 동일                                                  |
| `month_idx`            | 사기 데이터가 특정 월에만 존재하는 것처럼 보임 — train 수집 기간 차이일 수 있으므로 누수 여부 확인 필요 |


---

### 우선순위 액션 리스트 최종 업데이트

**1순위 — 플래그 피처 생성 (분리력 ★★★)**

- `name_email_sim < 0.3` 플래그
- `credit_risk_score < 0` 플래그
- `init_transfer_amt > 임계값` 플래그 ← **신규 추가**
- `days_since_req < 7` 플래그

**2순위 — clip 후 log1p**

## [시각화 11] `credit_risk_score` × `age_bucket` — Hexbin / 2D Histogram / KDE / LOESS

### Hexbin (색 = 구간별 사기 비율)

- 대부분 **낮은 사기 비율**(파란색).
- **오른쪽(신용점수 200~400)** 일부 육각형에서 사기 비율이 올라감 — 고점수 구간도 방심 불가.
- `age_bucket`은 수평 띠 → **이산 버킷** 재확인.

### 2D Histogram

- 밀도는 점수 **0~200**, 연령 **20~50** 에 가장 많음.
- 매우 낮은 점수·매우 높은 점수 구간은 **희소**.

### KDE (클래스별)

- 정상: 점수 ~~100, 연령 30~~40 부근 피크.
- 사기: 점수 **150~250**, 연령 **40~50** 쪽으로 **오른쪽·위로 이동**.
- **매우 낮은 점수(약 -100) × 낮은 연령(약 20)** 에 작은 사기 덩어리 → **소수 패턴**; Train에서만 과적합되지 않게 주의.

### LOESS

- 사기 선이 **더 가파름**.
- 점수 **0 미만**에서는 사기가 연령이 더 **젊음**; 점수 **50 이상**에서는 사기가 연령이 더 **높음** — **비선형 상호작용** 강함.

### 전처리 방향

- `credit_risk_score == -100` 근처(또는 음수 극단)는 **결측/코드값** 여부 확인 후 별도 플래그.
- `credit_risk_score` × `age_bucket` **교차항** 또는 트리에서 분할 후보로 우선.

### 전처리 방향

- **클래스 불균형**: 학습 시 가중·언더/오버샘플링 등은 **검증 분할 전략**과 함께 설계.
- 스케일: 두 변수 스케일이 다름 → 거리 기반 모델은 **스케일링**; 트리는 상대적으로 덜 민감.

## [시각화 18] 범주형 3종 막대 — 건수(Stacked) · 구성비(100%) · **카테고리별 사기율(%)**

> 왼쪽: 절대 건수(정상·사기 쌓기) / 가운데: 범주 **안에서** 정상·사기 비율 / 오른쪽: **범주마다 사기율만** (점선 = 전체 평균, 약 **1.1%** 전후로 읽힘)  
> 코드는 없고, **인코딩·가중치·해석**만 정리.

### 공통 읽는 법

- **절대 건수**가 큰 범주(CA, AB, INTERNET 등)는 모델·검증에서 비중이 크므로, 희귀 범주만 과대평가되지 않게 **교차 검증·층화** 확인.
- **100% 막대**는 사기 비율이 낮아서 주황이 잘 안 보임 → **오른쪽 사기율 막대**가 해석에 더 직관적.
- **Target Encoding / Mean Encoding** 시 희귀 범주는 train 평균으로 스무딩하거나 `Other` 병합.

---

### `payment_type` — AA, AB, AC, AD, AE


| 항목          | 내용                                                                   |
| ----------- | -------------------------------------------------------------------- |
| **건수**      | **AB**가 최다(~25만 이상), **AA·AC**도 큼, **AD** 중간, **AE**는 거의 없음 → AE는 희귀 |
| **사기율(대략)** | **AC**가 **최고(~1.65%)** 로 전체 평균보다 뚜렷히 높음                              |
|             | **AB**는 평균 부근(~~**1.1%**), **AD**는 평균 약간 아래(~~**1.05%**)             |
|             | **AA·AE**는 **~0.5%** 수준으로 평균의 **절반 이하** → 상대적으로 “낮은 위험” 범주           |


**전처리:** `payment_type` one-hot 또는 TE. **AC**는 고위험 신호로 별도 플래그 검토. **AE**는 `Other` 병합 또는 빈도 가중.

### 주의

- 정상·사기 **모양이 비슷**하면, 평균만으로는 구분이 어렵고 **분산·꼬리·교차항**이 중요함을 시사.

**전처리:** 레이더는 발표용·직관용. 피처 선택 근거로 쓰기보다 **히트맵·FI**를 우선.

## [시각화 23] PCA 2D · 설명분산 누적 · t-SNE 2D

### PCA

- PC1·PC2만으로는 정상(파랑) 구름 안에 사기(빨강)가 섞임 — **선형 2차원만으로는 분리 어렵다**는 시사.
- 막대: PC1이 분산의 약 **12%** 전후, **PC10까지 누적 약 60%** — 정보가 여러 축에 퍼져 있음 → **PC 1~2만 추가 피처**로는 한계, 많이 쓰면 노이즈.

### t-SNE

- 클러스터·섬 형태가 PCA보다 뚜렷 — **비선형 구조** 존재 가능. 샘플 그림이라 **검증·재현성** 확인 필요.
- 사기 점이 여전히 퍼져 있으면 → **지도학습 피처**로 t-SNE 좌표를 넣는 것은 누수·과적합 주의(Train에서만 fit).

**전처리:** PCA는 결측 처리·스케일 후. t-SNE는 **시각화·군집 탐색**용으로 두고, 제출 피처로 넣을지는 CV로만 결정.

## [시각화 27] SHAP Dependence — `curr_addr_months` (색 = `name_email_sim`)

> 한 피처의 SHAP이 **원값에 따라 어떻게 변하는지**. 색으로 **다른 피처**를 겹쳐 보면 **상호작용**이 보임.

### 관찰 (그림 기준)

- `curr_addr_months`가 **짧을수록**(왼쪽) SHAP이 음의 방향, **중간 구간(대략 수십 개월)** 에서 SHAP이 최대로 올라갔다가, **매우 긴 체류**에서는 다시 0 근처로 내려가는 형태로 읽힘 → PDP와 같은 **“중간이 유리”** 패턴 가능.

**전처리:** 교차항·트리 분할 우선. 단독으로 `curr_addr_months`만 선형 처리하면 부족할 수 있음.

## [시각화 29] Lift · Gain · Confusion matrix · Calibration

### Lift / Gain

- Lift: 상위 n%에서 **랜덤 대비 몇 배**로 사기를 잡는지 — 상위 구간에서 크게 뜨면 **랭킹 모델**로 쓸 가치 있음.
- Gain: 예시로 **상위 약 20%** 안에 전체 사기의 **약 80%** 가 들어온다는 식이면, **집중 검사·우선순위**에 유리.

### Confusion matrix (예: thr ≈ 0.91)

- **TN**이 매우 크고 **TP**는 상대적으로 작음 — 전형적인 **저사기율·고정밀 임계값** 설정.
- **FN**(사기를 정상으로 봄)과 **FP**(정상을 사기로 봄) 트레이드오프를 숫자로 확인하고, **업무 비용**에 맞게 임계값 조정.

### Calibration

- 예측 확률이 대각선(완벽 보정)에서 **위로 붙지 않고**, 낮은 확률 구간에서 실제 사기 비율이 거의 0에 가깝게 나오면 → **확률이 과대 또는 구간이 몰림** 가능.
- **전처리:** 확률을 그대로 비즈니스에 쓰기 어렵다면 `CalibratedClassifierCV` 등 **보정** 검토(모델 단계).

## [시각화 32] Train vs Test — 히스토그램 겹침 + KS 검정

> 파랑=train, 주황=test. 제목에 **KS 통계량·p-value**. (노트북 설정에 따라) **빨간 제목 = p<0.05 등으로 분포 차이 있다고 본 칼럼**.

### 읽는 법

- 두 분포가 **거의 겹치면** test에서도 train과 비슷한 패턴으로 예측할 여지가 있음.
- **꼬리·피크 위치**가 어긋나면 → 그 변수는 **일반화 약화** 가능, 변환·clip을 train·test **동일 규칙**으로 적용할 것.

### 그림에서 보이는 전반적 경향 (26개 수치형)

- 대부분 변수에서 train·test **모양이 매우 비슷**하게 보이는 편 — 앞의 **드리프트 표(diff_% 모두 ~1.2% 이하)** 와도 맞음.
- 이진·이산(`is_free_email`, `req_credit_limit` 봉우리 등)도 양쪽이 같이 움직이는지 확인.

**전처리:** KS p값이 작은 변수만 따로 리스트업해 **log/clip**을 test에도 동일 적용. `device_fraud_history`는 상수에 가까우면 train/test 무관.

## [데이터 드리프트 요약] Train vs Test 평균·표준편차

> `diff_%` = |trainmean - testmean| / (|trainmean| + ε) × 100 에 가까운 스케일(노트북 정의와 동일하다고 가정).

### 요약

- **모든 칼럼에서 `diff_%`가 약 1.2% 이하** — 평균 수준에서는 **train/test가 매우 가깝다**고 볼 수 있음.
- **가장 큰 차이(상대적):** `is_foreign_req` (**~1.18%**). 그다음 `init_transfer_amt` (~~0.86%), `session_length_min` (~~0.62%) 등.
- `**name_email_sim`·`device_fraud_history`·`yearly_income` 등은 diff_% 거의 0** — 평균 드리프트 미미.

### 전처리 시사점

- **평균은 비슷해도** 꼬리나 이산점에서는 다를 수 있으니, 시각화 32 히스토그램·KS **p-value**를 함께 본다.
- 검증 점수가 train에만 좋고 test에 나쁘면 원인은 **드리프트보다 과적합·누수** 쪽을 우선 의심.

## 6장 요약 — 액션만 모아보기

1. **결측/센티넬**: `prev_addr_months`·`bank_months_count`는 플래그 + impute 전략 분리.
2. **제거 후보**: `device_fraud_history`(상수), `id`(식별자).
3. **변환**: skew 빨간 변수 전반 + QQ에서 꼬리 튀는 변수 → log1p / clip.
4. **이상치를 지우면 안 되는 쪽**: `has_other_cards`(사기 극단), `init_transfer_amt`, `is_foreign_req`.
5. **정규 가정**: `credit_risk_score`만 QQ상 비교적 양호 — 나머지는 정규화만 믿지 말 것.
6. **해석 충돌**: `credit_risk_score` 방향은 그림마다 다를 수 있음 → 모델 기반으로 최종 확인.
7. **상관·차원**: `req_rate`_* 상호 상관 높음 → 압축·선택 고려. PCA 누적 분산·t-SNE는 **탐색용**, 피처 추가는 CV로만.
8. **중요도**: LGBM split 중심 vs Permutation(AP) 순위가 다름 → **범주·이진**은 Permutation/SHAP도 반드시 참고.
9. **SHAP**: 범주·주소·이진이 상위에 오면 EDA의 고위험 범주·`name_email_sim`과 **교차 검증**. Dependence로 **교차항** 확인.
10. **평가·보정**: AP·ROC·임계값은 실험마다 변함. Calibration이 대각선에서 벗어나면 **확률 보정**은 모델 후단에서 검토.
11. **순서·드리프트**: Rolling·ACF는 **행 순서**에 민감 — 시간 분할·드리프트 점검. `yearly_income` lag 대각선은 시계열 해석 금지.
12. **Train vs Test**: 평균 `diff_%`는 전반적으로 **1% 안팎** — 변수 평균 기준 **드리프트는 크지 않음**. 다만 `**prev_addr_months`는 사기에서 -1 비율이 훨씬 큼** — 결측은 **클래스별**로 다룰 것.

### Train vs Test·품질 (공통)

- **평균 드리프트**는 대부분 **1% 미만** → 변수별 **같은 clip/log 규칙**을 test에 적용해도 무방한 편.
- **KS p-value** 작은 변수는 히스토그램으로 **꼬리**만 한 번 더 확인.
- **결측(-1)** 은 `**prev_addr_months`·`bank_months_count`** 가 라벨과 강하게 엮임 → **반드시 플래그**로 남길 것.
